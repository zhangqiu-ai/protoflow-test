# Expo acceptance specification (Expo SDK 58, Expo Router, CNG)

Reviewed operator specification for the `protoflow-expo-20261018` prototype stream. It applies to every version of the stream.

- The prototype is the design input. Each prototype page is one screen (`<body data-pf="<screen>" data-pf-role="screen">`); every `data-pf` anchor must exist in the application with the identical ID as `testID`, the same text, order and visibility, and styling that follows `prototype/tokens.json` and the prototype CSS. States in `<page>.pf.json` sidecars must be reachable with the listed steps.
- One codebase in `expo/` serves the `ios` and `android` variants of the `expo` target; every change must work on both.
- Every prototype screen is an Expo Router route `expo/app/<screen>.tsx`. The driver opens a screen with the deep link `protoflowtasks://<screen>?state=<state>&fixture=<json>`; a new prototype screen must be openable this way. The Stack shows no header and no transition animation.
- Pressable anchors set `accessibilityRole="button"`. Text that only spans its content in the prototype uses `alignSelf: 'flex-start'`. Native controls keep their platform size (the toggle anchor `settings.notify-toggle` is a declared layout deviation on Android).
- Continuous Native Generation: `expo/ios/` and `expo/android/` are generated by `expo prebuild --clean` and must never be created by hand or committed. Native settings change only through config plugins (`expo/plugins/`).
- Functional tests live in `expo/__tests__` (`jest-expo`, `expo-router/testing-library` `renderRouter`, `await fireEvent`). Keep them passing and extend them for new behaviour.
- Everything stays local: no network requests, accounts or persistent storage. No new dependencies. Text input must end editing (dismiss the keyboard) when the action that follows it runs.
- Shared files (`scripts/`, `protoflow.config.json`, `AGENTS.md`, `ACCEPTANCE.md`, `.gitignore`) and the frozen prototypes are operator-owned and must not be changed.
